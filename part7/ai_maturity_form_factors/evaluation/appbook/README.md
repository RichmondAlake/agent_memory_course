# Evaluation Studio — the AI Maturity Ladder

A FastAPI + vanilla-JS app that evaluates the maturity module's five form factors (chatbot, RAG, workflow with
the Clef decision model, tool-using agent, autonomous agent) the way the evaluation notebook does, and shows every
evaluation run, from the notebook or from this app, side by side. Port **8705**.

## Run

```bash
cd part7 && ./oracle.sh start                 # Oracle AI Database, once
cd ai_maturity_form_factors/evaluation/appbook
cp .env.example .env                          # add your keys, or export them
./run.sh                                      # http://127.0.0.1:8705
```

`run.sh` uses `$PYTHON` if set, otherwise `part7/.venv`, otherwise `python3`, and installs `requirements.txt`
when an import check fails. `PORT` and `HOST` override the address.

## What is included

| Page | What it does |
|---|---|
| **Overview** | Every run in `FFEVAL_RUNS` (notebook and appbook). For the selected run: a scorecard per rung with its headline metric and READY / BLOCKED |
| **Graders** | Runs the grader validation live: labelled checks built by construction, answered by Clef-Flash, Jev and the LLM judge, streamed check by check. Shows accuracy, Cohen's κ, ECE and latency per check kind × grader, the reliability diagram, the blind spots per variant, the grader chosen per kind (cheapest within 0.05 κ of the best, on the dev half) and the escalation cascade. **Try a check** asks every grader one question and shows P(yes), latency, cost and the judge's reason |
| **① Chatbot** | Closed-book answers to the 36 golden questions (correct / abstained / confident error) and scripted conversations that test the buffer with a correction |
| **② RAG** | Retrieval for keyword, vector, hybrid and graph search, with and without the reranker (recall@3, MRR, nDCG@5, ceiling), then cited answers graded claim by claim: faithfulness, citation coverage, freshness (no stale 41%), abstention |
| **③ Workflow** | 24 applications generated by rule: extraction field accuracy, Clef on gold inputs (accuracy and calibration), the gate, end to end with unsafe errors and the first wrong step, and the letters |
| **④ Agent** | Seven tasks graded by the end state in Oracle, the tool calls and the reply (including a prompt-injection task); pass@1 and pass^k over repeated attempts; session resume and fork |
| **⑤ Autonomous** | The builder in a sandbox, then hidden tests it never saw (a new batch, a changed policy, bad inputs), an audit of every tool call, and reuse by a new read-only session |
| **Release gates** | READY / BLOCKED per rung for the selected run, with the evaluation notebook's gates |
| **Data Explorer** | Read-only rows of every `FFEVAL_` and `FFAPP_` table, filterable by run id |

Each rung page runs its suite as a background job (**quick** or **full**), streams the cases as they are graded,
keeps running if you navigate away, and has a **Stop** button. When idle it shows the latest stored run that measured
that rung. Rung suites grade with the graders chosen by the latest validation run (or the notebook's choices when
there is none: Jev for `states_fact` and `abstains`, Clef for `supported`; the judge when Jev has no key).

### Tables

| Prefix | What | Shared with the notebook? |
|---|---|---|
| `FFEVAL_RUNS`, `FFEVAL_RESULTS`, `FFEVAL_GRADER_CHECKS`, `FFEVAL_TOOL_EVENTS`, `FFEVAL_GATES` | the evidence; appbook runs are labelled `appbook-<utc>-<hex>` | yes: one summary function reads both |
| `FFAPP_POLICY`, `FFAPP_POLICY_*`, `FFAPP_APPLICATIONS`, `FFAPP_DECISIONS`, `FFAPP_CASE_NOTES` | the application under test (policy memory, case files) | no: the notebook uses `FFEVAL_` names for its own copy |

The RAG and agent suites rebuild the policy memory whenever it is not at the expected versions; the autonomous suite
raises the credit-score limit for its reuse test and puts it back at the end. Vector search here is an exact scan
(seventeen rows need no HNSW index); the notebook builds and explains the index.

## Configuration

|---|---|---|
| `ANTHROPIC_API_KEY` | — | the application under test; empty means open models |
| `AIML_MODEL`, `AIML_EFFORT` | `claude-haiku-5-5`, `low` | the application's model |
| `AIML_PROVIDER`, `OLLAMA_URL`, `AIML_OPEN_MODEL` | — | Gemma 4 through Ollama (`gemma4-32k` is created on start) |
| `OPENAI_API_KEY`, `EVAL_JUDGE_MODEL` | — , `gpt-6.1-sol` | the cross-family judge; without an OpenAI key, `claude-sonnet-5-5` |
| `TYPESAFE_API_KEY` | — | Jev (optional) |
| `CLEF_URL` | — | a SystemOne endpoint serving Clef; otherwise Clef-Flash loads in-process (MLX) on first use |
| `ORACLE_USER`, `ORACLE_PASSWORD`, `ORACLE_DSN` | `VECTOR`, `VectorPwd_2025`, `localhost:1521/FREEPDB1` | the database |

## Tracing to Arize AX

Set `ARIZE_SPACE_ID` and `ARIZE_API_KEY` (in the environment or `.env`) and every call is traced to the Arize AX
project `ai-maturity-evaluation-appbook` (`ARIZE_PROJECT_NAME` overrides it). Claude, the OpenAI judge and the agents
are traced automatically; Clef-Flash, Jev, Ollama, each grader verdict, the four retrieval stages, the reranker and the
workflow's decision get their own spans. Off by default; `/api/health` reports `tracing`. A full suite sends thousands
of spans.

## Tests

```bash
python -m pytest tests/test_contracts.py -q   # offline: routes, schemas, allowlist, metrics with known values
python tests/check_live.py                    # against the running app: the playground, quick RAG and workflow suites,
                                              # one agent task, and the evidence they wrote (--skip-agent to skip it)
python tests/check_browser.py                 # headless Chromium: every page, the playground, a streamed run and Stop,
                                              # the Data Explorer, a phone-width page, no console errors
```
